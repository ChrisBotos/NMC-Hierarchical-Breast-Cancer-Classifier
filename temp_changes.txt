1. DESIGN DECISION CHANGES
================================================================================

1.1 AUROC -> Balanced Accuracy (GLOBAL CHANGE)
    - The project metric was changed from weighted one-vs-rest AUROC to balanced
      accuracy throughout.
    - Balanced accuracy is the macro-averaged recall across the 3 classes,
      giving equal weight to each subtype regardless of class size.
    - This removes the need for predict_proba on NearestCentroid (which lacks
      it natively), eliminating the NMC probability wrapper problem entirely.
    - Files updated:
        * CLAUDE.md line 25 (competition metric description).
        * docs/research_plan.md (17 AUROC references replaced throughout).
    - Inner CV scoring changed from accuracy to balanced_accuracy in all scripts.
    - Outer CV evaluation changed from accuracy_score to balanced_accuracy_score.

1.2 Number of repeats kept at 3 (configurable)
    - The spec calls for 10 repeats (50 outer folds). The scripts currently use 3
      repeats (15 outer folds) for faster iteration during development.
    - All scripts now accept --n-repeats as a command-line argument.
    - Default is 3. Set to 10 for final runs.

1.3 Hyperparameter grids kept small (configurable)
    - The spec calls for wider grids (8 KW values, 10x5 EN grid).
    - Current grids are smaller for development speed. They are defined as
      module-level constants (Script A) or local variables (Scripts B) and are
      easy to expand before final runs.

2. BUG FIXES APPLIED
================================================================================

2.1 Scoring metric (ALL SCRIPTS) [CRITICAL]
    BEFORE: accuracy_score / scoring="accuracy"
    AFTER:  balanced_accuracy_score / scoring="balanced_accuracy"
    - Script A (KW_pipelines.py): GridSearchCV scoring param + outer eval.
    - Script B1 (EN_RF/script.py): Inner fold scoring + outer fold evaluation.
    - Script B2 (EN_NMC/script.py): Inner fold scoring + outer fold evaluation.

2.2 n_jobs discipline (Scripts A and B1) [IMPORTANT]
    BEFORE: n_jobs=-1 in GridSearchCV (Script A) and RandomForestClassifier (B1)
    AFTER:  n_jobs=1 everywhere
    - Parallelism will be handled externally via shell.

2.3 RF random_state not linked to repeat (Script A) [SUSPECTED BUG]
    BEFORE: RandomForestClassifier(random_state=42) hardcoded across all repeats.
    AFTER:  Pipeline recreated per repeat with random_state=seed.
    - make_kw_pipeline_and_grid() now accepts a random_state parameter.
    - run_repeated_nested_cv() builds a fresh pipeline each repeat.

2.4 Inner/outer seed collision (Scripts B1 and B2) [SUSPECTED BUG]
    BEFORE: Both inner and outer StratifiedKFold used random_state=outter_seed.
    AFTER:  Inner CV uses random_state=100 + outer_seed.
    - Decorrelates inner and outer split generation (Script A already had this).

2.5 Convergence warnings not surfaced (Scripts B1 and B2) [IMPORTANT]
    BEFORE: SAGA convergence warnings silently swallowed by default.
    AFTER:  warnings.catch_warnings(record=True) wraps every ElasticNet fit.
            ConvergenceWarning instances are logged via log.warning().
    - Applied in both run_inner_cv() and refit_and_evaluate() functions.

2.6 Feature naming convention divergence (Scripts B1 and B2) [IMPORTANT]
    BEFORE: Script A used chr1_100000_200000 (underscores).
            Scripts B used chr1:100000-200000 (colon + dash).
    AFTER:  All three scripts use chr{Chrom}_{Start}_{End} (underscores).
    - Feature importance results are now comparable across all four pipelines.

4. ISSUES NOT YET FIXED (TO ADDRESS DURING MERGE)
================================================================================

4.1 RF hyperparameters wrong set being tuned
    - Current: n_estimators, max_depth, min_samples_split
    - Spec: max_features in {sqrt, log2, 0.3}, min_samples_leaf in {1, 2, 5},
      n_estimators=500 fixed.
    - Will be corrected in the unified merged script.

4.2 Statistical comparison between pipelines
    - No statistical test is implemented between the 4 pipelines.
    - A corrected resampled t-test (Nadeau-Bengio) should be added in the merge
      to avoid inflated Type I error from naive paired t-tests on CV folds.

4.3 Small outer test fold caveat
    - With n=100 and 5-fold outer CV, each test fold has ~20 samples (~6-7 per
      class). Per-fold balanced accuracy estimates have substantial variance.
    - Pipeline differences below ~5% balanced accuracy are likely noise.

4.4 EN_RF grid is enormous (960 combinations)
    - The joint grid tunes EN params + RF params simultaneously.
    - EN model is redundantly re-fitted 48x for each unique (C, l1_ratio) pair.
    - Merge should restructure: fit EN once per (C, l1_ratio), then sweep top_k
      and RF params on the selected features.

4.5 Directory name encoding issue
    - EN_NMC_final directory uses Greek letters (U+0395 + U+039D) not ASCII "EN".
    - Will not be propagated into the merge (unified script goes in code/).

4.6 Duplicate data files in EN_RF_final/
    - train_merged.tsv and Train_clinical.tsv are local copies in the EN_RF
      directory. These are now unused (scripts load from canonical paths) but
      the stale copies remain. Should be cleaned up.

4.7 Class imbalance handling
    - No class_weight set in any classifier. With ~32/36/32 distribution this is
      defensible, but balanced_accuracy already accounts for class imbalance in
      the metric. Consistent across all pipelines.

4.8 Expand grids for final runs
    - KW: k in {5, 10, 15, 20, 30, 50, 75, 100} (currently [5, 20]).
    - EN: C as np.logspace(-3, 2, 10) (currently [0.01, 0.1, 1, 10]).
    - Repeats: 10 (currently 3).
